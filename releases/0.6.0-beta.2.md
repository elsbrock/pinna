# Pinna 0.6.0-beta.2

MCP servers with many tools, such as ha-mcp with its 77, now work. A server that lists more than 32 tools is added with them off, All on and All off switch a server's tools at once, and the page says when the brain's limit leaves tools out.

## Before you update

This is a beta: it goes to satellites whose **Updates** setting is `beta`.

- **A server you added earlier keeps its tools on.** Only a server you add,
  or whose address you change, after the update starts with its tools off. A
  server that failed before with "response is too large", such as ha-mcp, now
  lists all of its tools, all of them on. A server that offered 32 tools can
  now offer up to 128. If **Assistant** › **Tools** says that tools are left
  out, select **All off** under the server's **Its tools** and turn on the few
  a voice request needs.

## Highlights

### MCP servers with many tools work

ha-mcp lists 77 tools in a reply of almost 300 KB. The satellite read at most
256 KiB and kept 32 tools of a server, so such a server failed with "response
is too large". It now reads tool lists up to 1 MiB and keeps up to 128 tools
of a server. An expired tool list no longer holds up a voice request: the
satellite answers with the list it has and asks the server again in the
background.

### A big server's tools start off

When you add a server that lists more than 32 tools, or change its address,
all of its tools start off. Most of ha-mcp's tools manage Home Assistant
itself, such as removing automations, so turn on only the few a voice request
needs. Under **Assistant** › **Tools**, **Its tools** starts with **All on**
and **All off**, and the server's row says how many tools are on, such as
`0 of 77 tools on`. **All on** asks first for a server with more than 32
tools.

### The brain's 64-tool limit is in view

The brain takes at most 64 tools in a request: Pinna's first, then each
server's in the order the page lists them. Tools past 64 were left out without
a word. While more than 64 are on, the Tools page now says how many are left
out, and **System** › **Logs** names the first one for each request. See
[Add an MCP server](https://getpinna.dev/docs/standalone/#add-an-mcp-server).

## Other changes

- A tool's row shows its own name, and its description is cut at three lines,
  so a long list can be scanned on a phone.
- **All on**, **All off** and **Its tools** name their server to a screen
  reader, and keep the focus while a save runs.

## Fixed

- Renaming an MCP server left its tool switches under the old name, so all of
  its tools were on again. The switches now follow the rename. Deleting a
  server deletes its switches, so adding it again starts afresh.
- With a big server's switches stored, every tool switch, **All on** and
  **All off** could be refused with "At most 128 tool switches." The limit is
  now 1100.
- A server's **Its tools** row reads as part of the server, not as an entry of
  its own.

## All changes

Changes since 0.6.0-beta.1.

### New

- Read tool lists up to 1 MiB and refresh them in the background (pinna-mcp)
- An MCP server with more than 32 tools is added with them off (pinnad)
- The brain logs the tools its 64-tool limit leaves out (pinna-assist)
- An MCP server's tools turn all on or off, with the brain's limit in view (dashboard)

### Fixed

- An MCP server's tool list reads as part of its server (dashboard)
- An MCP server's tool switches follow its rename and go with it (pinnad)
- A big MCP server says why its tools are off, and All on asks first (dashboard)
